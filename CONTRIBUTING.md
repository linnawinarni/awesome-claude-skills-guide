# Using the Skills Curator Skill

## What This Skill Does

The **Skills Curator** skill helps you:

- Evaluate submissions fairly and consistently
- Write constructive feedback to contributors
- Identify commercial funnels and spam
- Maintain quality standards
- Make objective accept/reject decisions

## When to Use This Skill

Use it when:

- 📋 Reviewing new skill submissions
- 🔍 Evaluating resource quality
- 💬 Writing feedback for contributors
- 📊 Assessing category fit
- 🛡️ Identifying red flags or spam
- 📝 Formatting repository entries

## How to Get Started

### Step 1: Enable the Skill
- Upload `SKILL.md` to your Claude settings
- Enable it in your workspace

### Step 2: Use the Assessment Framework
When reviewing a submission, ask Claude to:
- Assess it across the four dimensions (Relevance, Quality, Safety, Value)
- Identify potential red flags
- Provide a recommendation

### Step 3: Get Feedback Guidance
When you need to respond to a contributor, ask Claude to:
- Draft constructive feedback
- Suggest improvements
- Provide a clear next-steps message

## Example Prompts

### For Quick Assessment
```
"Use the skills curator to evaluate this submission:
[submission details]
Should we accept it?"
```

### For Detailed Review
```
"Review this skill submission using the four-dimensional framework:
[submission details]
Provide scores for each dimension and a recommendation."
```

### For Feedback Writing
```
"The contributor submitted this skill but the description is too vague.
Help me write constructive feedback suggesting improvements."
```

### For Red Flag Identification
```
"I'm suspicious this might be a SaaS wrapper.

```

## Tips for Best Results

1. **Be specific** - Provide the actual submission text or details
2. **Give context** - Mention your repository's standards or category
3. **Ask for templates** - Use provided feedback and review templates
4. **Reference principles** - Ask the skill to apply core curation principles
5. **Follow guidelines** - Use the decision framework for consistency

## Key Decision Criteria

**Accept when:**
- Clearly relevant and useful
- No major quality issues
- Not a promotional funnel
- Follows repository standards

**Request Changes when:**
- Good concept but needs improvement
- Quality or clarity issues
- Missing information
- Format doesn't match standards

**Reject when:**
- Commercial pitch or spam
- Not genuinely useful
- Outside scope
- Violates repository principles

## Need Help?

For specific scenarios, ask the skill:
- "How should I handle [specific situation]?"
- "Is this a SaaS wrapper?"
- "How do I provide feedback for [specific issue]?"
- "Does this fit our repository?"

## Repository Standards

Maintain these principles:

- **Quality over quantity** - Fewer excellent entries > many mediocre ones
- **Value-first** - Every entry should provide genuine utility
- **Anti-spam** - Protect community from low-effort submissions
- **Transparency** - Clear criteria and consistent decisions
- **Community trust** - High signal-to-noise ratio
